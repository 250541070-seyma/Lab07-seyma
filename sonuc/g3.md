# Gorev 3 - Yuzlestirme: SQL vs Dokuman

**Soru:** En cok kayit alan dersin kayit sayisi kac?

## 1. PostgreSQL (Iliskisel Model) Sorgusu ve Sonucu

   ```sql
SELECT d.ders_id, d.ad, COUNT(*) AS adet
FROM dersler d
JOIN kayitlar k ON d.ders_id = k.ders_id
GROUP BY d.ders_id, d.ad
ORDER BY adet DESC
LIMIT 1;

**Sonuc:** ders_id = 3 (Core Güçlendirme — İleri) olan ders, **20** kayit ile en cok kayit alan derstir.

## 2. MongoDB (Dokuman Modeli) Aggregate Boru Hatti ve Sonucu

   ```javascript
db.kayitlar.aggregate([
  { $group: { _id: "$ders_id", adet: { $sum: 1 } } },
  { $sort: { adet: -1 } }, {$limit: 5 }
])
```

**Sonuc:** _id: 3 olan ders **20** kayit almistir (her iki dunyada da sonuc birebir aynidir).

## 3. Degerlendirme


PostgreSQL tarafında tabloları `JOIN` ile birleştirip `GROUP BY` kullanmak klasik SQL alışkanlığımla daha tanıdık gelse de, MongoDB'de `kayitlar` koleksiyonu zaten `ders_id` alanını tuttuğu için birleştirme yapmadan doğrudan `$group` aşamasıyla sonuca gitmek çok daha sade ve pratik oldu. Ders kartı ekranında ders, eğitmen ve salon bilgilerinin tek seferde gösterilmesi gerektiğinde doküman modeli (MongoDB) tek bir okuma işlemiyle tüm veriyi getirebildiği için çok daha hızlıdır; çünkü eğitmen ve salon bilgileri ders dokümanının içine gömülü alt doküman olarak yerleştirilmiştir. Ancak bir eğitmenin adı değiştiğinde denormalize yapıya sahip MongoDB tarafı zorlanır; çünkü o eğitmenin verdiği tüm ders dokümanlarını tek tek bulup güncellemek gerekirken PostgreSQL'de yalnızca `egitmenler` tablosundaki tek bir satırı değiştirmek yeterlidir. Bu nedenle FıratFit uygulamasında üye kayıtları, abonelik ödemeleri ve yabancı anahtar (`FOREIGN KEY`) kısıtlarıyla veri tutarlılığının zorunlu olduğu ilişkisel işlemler için PostgreSQL'i tercih ederdim. Sık okunan ders kataloğu, eğitmen tanıtım kartları ve farklı alanlar içerebilen esnek antrenman içerikleri için ise MongoDB kullanmak çok daha uygun olur.
